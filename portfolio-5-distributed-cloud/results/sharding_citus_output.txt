========================================================================================
A5  Constraint rule in a sharded table
========================================================================================
Try: ALTER TABLE patients ADD UNIQUE (hospital_no)   -- hospital_no is not the distribution key
    ERROR:  cannot create constraint on "patients"
    DETAIL:  Distributed relations cannot have UNIQUE, EXCLUDE, or PRIMARY KEY constraints that do not include the partition column (with an equality operator if EXCLUDE).
Each worker can only check uniqueness inside its own shards, so global uniqueness of a non-key column
is not enforced. Options: make hospital_no derive from patient_id, check it in a lookup table, or
keep patient registration on a single (non-distributed) table.

========================================================================================
A6  Cross-shard transaction (two-phase commit across workers)
========================================================================================
patient 1 lives on citus-w1, patient 3 on citus-w2. One transaction updates both:
    BEGIN
    UPDATE 7
    UPDATE 3
    COMMIT
Because the transaction wrote to two workers, Citus committed it with two-phase commit
(PREPARE TRANSACTION on each worker, then COMMIT PREPARED), so the change is atomic across
machines; pg_dist_transaction records it so an interrupted commit can be recovered.
